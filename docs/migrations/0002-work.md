# Migration 0002: Work workspace

Created by CloudMonkey. This is an additive schema change for release 0.2.0. Existing mail tables and rows are unchanged.

New tables are `work_connections`, `work_chats`, `work_entries`, `work_actions`, and `work_oauth`, defined in backend/work_models.py. They reference existing users and each other. Startup registers these models before create_all and creates absent tables. This is not a general migration engine: later changes to these tables must have their own reviewed migration.

Before upgrade, stop app and worker, take and verify a PostgreSQL logical backup, and preserve .env plus the protected secrets directory. Test the upgrade against a restored database first. Build/start release 0.2.0; verify existing user/mailbox counts and mailbox access are unchanged, then create a Work conversation with controlled credentials. No provider call or mail send is made by schema creation. App startup marks interrupted running Work actions uncertain.

Rollback to 0.1.0 may leave the additive tables in place; the old release does not read them. Do not drop them unless the owner explicitly accepts losing Work histories, encrypted integration keys and pending action records. If exact pre-upgrade state is required, restore the verified backup on isolated infrastructure and follow the existing recovery/cutover procedure. Disabling the Codex override does not delete its auth volume; sign out accounts and handle that volume as sensitive retained data.
